# Полная политика безопасности Искры

## Принципы

1. **Zero Trust.** Каждый запрос проверяется veil/ethics, даже если пользователь авторизован.
2. **Least Privilege.** Codex работает в режиме `auto`; Full Access — только с зафиксированным комментарием.
3. **Auditability.** Все критические действия логируются в `AUDIT_REPORT.md` и журналах.

## Угрозы и меры (OWASP Top-10 for LLM 2025)

| Категория | Риск | Мера |
| --- | --- | --- |
| Prompt Injection | Манипуляция инструкциями | `veil_rules.txt`, `facets_refine` отслеживает парадоксы, ручной ревью |
| Data Leakage | Вытекание приватных данных | маскирование PII, запрет сохранения личных данных |
| Model Override | Попытка сменить личность | `personas.enforce_safety_persona` и проверка тонов |
| Unbounded Resource Use | Бесконечные задачи | ограничение `max_tokens`, `forbid_background_tasks` |
| Unsafe Code Exec | Запрос выполнения кода | `ethics_layer` блокирует exec, а `BEHAVIOR_ENGINE` запрещает фоновые задачи |
| External Network Abuse | Неразрешённые запросы | `allow_external_network: false`, белый список доменов |
| Poisoned Inputs | Заражение через файлы | ручная проверка источников, `tools/audit_repo.py` |
| Drift of Guardrails | Ослабление правил | еженедельный `make security`, аудит veil |
| Logging Failures | Потеря логов | резервирование журналов и shadow coverage |
| Supply Chain | Зависимости с уязвимостями | `pip-audit`, `requirements` закреплены по версиям |

## Процедуры безопасности

- Запуск `make security` перед релизом: включает линтеры veil, секрет-сканер и проверку лицензий.
- Каждая новая зависимость фиксируется в `requirements*.txt` и проверяется `pip-audit`.
- Изменения `veil_rules.txt` требуют двойного ревью (оператор + безопасность).

## Обработка инцидентов

1. Зафиксировать событие в `SHADOW_JOURNAL.jsonl` (∆ ≤ -2).
2. Оповестить команду в Issue/PR с тегом `security`.
3. Провести анализ причин (root cause) и обновить `AUDIT_REPORT.md`.
4. Обновить `docs/20_DEPLOYMENT_CHECKLIST.md`, если процедура изменилась.

## Соответствие нормативам

- **EU AI Act:** прозрачность решений (журналы + документация), управление рисками (SLO по метрикам), человеческий контроль (оператор утверждает релизы).
- **PII Handling:** личные данные не сохраняются. Если пользователь прислал PII — маскируем и предлагаем безопасный канал.
- **Responsible Disclosure:** внешний исследователь пишет на security@project.example; ответ в течение 72 часов.

## Расширение политики

При добавлении новых инструментов:

1. Оцените риск (инъекции, утечки, лицензии).
2. Обновите таблицу угроз и мер.
3. Добавьте тест в `tests/test_spacecore_modules.py` или отдельный security-тест.
4. Сообщите об изменениях в README и CHANGELOG.
