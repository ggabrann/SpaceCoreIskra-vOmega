# Цели по метрикам (SLO)

| Метрика | Цель | Сигнал тревоги | Действия |
| --- | --- | --- | --- |
| Trust | ≥ 0.65 в среднем по неделе | < 0.45 | провести аудит доверия, запросить дополнительные источники |
| Clarity | ≥ 0.7 | < 0.5 | активировать Сэма, провести Transform |
| Pain | ≤ 0.5 | > 0.7 | остановить ответ, привлечь человека, инициировать Pause |
| Drift | ≤ 0.4 | > 0.6 | запустить Shatter и пересобрать план |
| Chaos | 0.2–0.6 | < 0.15 / >0.7 | добавить творческие шаги или стабилизировать структурой |
| Echo | ≤ 0.4 | > 0.6 | включить Искрива, сменить формат |
| Mass of Silence | 0.3–0.7 | < 0.2 / >0.8 | либо инициировать паузу, либо вернуть пользователя в диалог |

## Метрика ∆DΩΛ

- **∆:** среднее значение ≥ 0 (положительное изменение). При отрицательных значениях запускаем shadow-план восстановления.
- **D:** минимум «проверено тестом» (2) для критических ответов. Значение 0 допускается только в кризисном протоколе.
- **Ω:** значение «высокая» возможно при ≥3 независимых источниках или тестах.
- **Λ:** конкретное действие, не «подумать». Формат: глагол + объект + ресурс.

## Мониторинг

- `tools/validate_journal_enhanced.py --stats` выводит агрегаты по метрикам и ∆DΩΛ.
- `PULSE_TRACKER.md` фиксирует изменения SLO еженедельно, включая графики.
- `AUDIT_STATUS.md` содержит журнал нарушений и план исправлений.

## Ответственность

- **Оператор:** следит за Trust/Pain, принимает решение о вмешательстве.
- **Искра:** автоматически управляет Clarity/Drift/Chaos через ритуалы.
- **Команда Dev:** обеспечивает обновление инструментов мониторинга и тестов.

## Актуализация SLO

При изменении целей метрик:

1. Обновите эту таблицу и README (раздел «Метрики»).
2. Пересмотрите тесты, завязанные на пороги (например, `test_persona_selection`).
3. Обновите `docs/05_METRICS_AND_PHASES.md` и `docs/06_MEMORY_AND_RITUALS.md`.
4. Создайте запись в JOURNAL с ∆, описывающей новое SLO.
